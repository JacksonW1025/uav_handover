## 1. 现在研究什么

长期研究对象是**经典控制与神经控制共同存在的混合软件系统**：在何种物理状态、控制器历史和接管过程下，控制权转移会带来安全问题；怎样通过反例搜索刻画这些条件，并逐步形成可执行的拒切规则。PX4/RAPTOR 是当前已实施的平台。未来可能将方法扩展到 Autoware 等系统，但**尚未实施 Autoware 接口、场景或实验，也没有跨平台有效性证据**。

研究 PX4 经典飞控向 RAPTOR 神经飞控接管，以及切回经典控制时的安全边界：**飞机处于什么运动状态、控制器带着什么历史、参考如何接续，会使交接后出现过大倾角、失高或其他安全越界？能否据此找出应拒绝直接交接的条件？**

这里的交接问题覆盖瞬时接管和接管后的任务执行。经典控制能够完成的飞行，交到神经控制后可能在紧弯、刹停或参考超时阶段出现危险。我们记录危险何时出现、什么条件触发，不把后续阶段的问题排除在研究之外，也不把不同阶段混成同一种原因。

|研究角度|具体变量|目前认识|
|---|---|---|
|物理状态|实际水平/爬降速度、姿态、角速度、高度余量、运动相位、物理参数|名义轨迹速度或同一 Mission 航段不能代表相同入口状态；需要原生日志核对。|
|控制器历史|原始 reset、影子推理、previous action、GRU 状态、退出后再入、提前进入神经|已核实部分历史干预真正执行，但历史准备不能单独消除目标失配风险，独立贡献仍需分离。|
|接管过程|正常模式准入、ACK、active、执行器持权、首条参考、目标捕获、活动期间参考超时、切回经典|这些事件不是同一个时刻。带速状态接到零速度目标，是目前最具体的危险组合之一。|

主要方法是小规模探索、围绕失败案例变异、局部对照，以及经验 Lyapunov 候选量引导的反例搜索。反例搜索是整个研究流程中的一个步骤：先产生可复核的危险条件，再分析状态、历史、接续方式的作用，最后提炼并验证拒切规则。当前目标是把这个步骤做实，同时检验 V 相比速度误差、倾角或角速度等简单指标究竟增加了什么；不以“找到了反例”直接宣布 V 已优于其他方法，也不宣称已经得到完整安全域。

## 2. 环境与证据口径

- 实验机为 NVIDIA Jetson AGX Thor；Ubuntu 24.04、ROS 2 Jazzy、Gazebo Harmonic，PX4/RAPTOR SITL。**没有真实飞行。** 近期批次采用 headless SITL，早期可视化实验另有记录。
- 主体机型是 x500，使用现有 RAPTOR 策略。100 组中的质量、惯量、电机时间常数改变属于 x500 参数扰动，不代表已适配新的神经飞控机型。
- C 表示经典控制，N 表示 RAPTOR。经典前缀有 OFFBOARD 和真正 AUTO_MISSION 两类；不能把外部轨迹模拟的运动称为 Mission。
- 正常模式命令、注册/准入与 ACK 检查保留。逐例核验实际 nav、active、神经发布、四电机首次应用及参考有效读取；不把请求成功等同于实际接管。
- 时序以 PX4 原生时钟为主，发送端时间用已有时钟映射/夹逼。实际姿态采用原生高频 ULog，四电机应用用 Gazebo 逐物理步证据。
- **45° 是本实验设置的安全线，不是 RAPTOR 保证永不超越的内置硬限幅。** 约 10 Hz 的在线检查已漏过短峰，最终结果以高频证据为准。
- 始终分别报告：物理任务安全（倾角 >45° 或入口相对失高 >1 m）、原冻结约束与恢复结果、执行流程完成/落地/disarm。计划下降、保护后的尾段、观察截断单独说明。

### 3.1 Mission：参考到达和真实接管存在时间差

原 Mission 单例在模式进入后 12 ms 发布神经电机指令、16 ms 被四电机应用，276 ms 才有效读取第一条外部参考。飞机先按原始 reset/capture 目标运行，再接到外部轨迹；约 260 ms 的窗口不能全部归为 DDS 通信延迟。

快速验证把首发等待从粗粒度模式确认改为新鲜实际 active 状态触发，正常 ACK 与准入仍保留。B/C 的首参考读取相对四电机首次神经应用分别 +168/−12 ms。**C 臂存在实际持权重叠：参考已发送并被 RAPTOR 读取时，电机仍由经典输出控制。** 原 README 仅说“没有在 Mission 导航模式下提前发”，遗漏了这个区别；按原要求“严禁向仍由经典 Mission 持权的共享目标通道提前发布参考”的实际持权含义，C 臂未满足该约束，不能称为完全遵守原设计的缩窗对照。

C3 原生日志顺序如下（秒）：

|事件|PX4 原生时间|含义|
|---|---:|---|
|nav_state=23（RAPTOR）、active=1|52.776|导航模式已退出 Mission，但不是电机权已交接|
|首条本实验参考发送|[52.776, 52.780]|主机发送映射的原生夹逼区间|

52.776 s 的另一个 external_valid 样本来自先前经典参考，不能当成本实验首条参考。上述证据确认共享通道预发与经典电机持权重叠，但没有经典位置控制器逐次输入读取证据，不能进一步声称它实际消费了本实验参考、或由此造成了多少状态变化。Thor 复核入口：`data/cn-reference-20261110/final-v2/summary.json`（C.native_timeline、first_motor_application、owner_boundary_motor_step）与 `audit/C3-local-topic-rows.jsonl.gz`。

前 2 秒倾角 B/C 为 15.883°/5.934°、失高 0.647/0 m，但两次入口速度向量差 3.231 m/s、位置差 0.430 m，一次下降、一次上升。现在既有初态不匹配，也有上述约束偏离；能确认等待路径和时序实际改变，**仍无法判断等待是否主导瞬态，不能把这次 C 的改善当作符合原设计的因果证据**。

后续 40 次 Mission 采样中，两次爬升零速捕获达到 47.826°、46.060°。对应实际水平速度约 1.24/1.36 m/s、爬升速度约 1.39/1.22 m/s、高度约 2.68/2.78 m。最近的参考制动对照仍有明显初态差异，所以目前按实际状态分层描述，不只按模式名或相同 seed 配对。

### 3.2 正常持续参考下，紧弯和刹停也能触发危险

最初紧弯三组的峰倾角：全经典 29.91°；运动中 C→N 保护前 51.07°；先进入 N 并稳定后再执行轨迹 50.12°。运动中交接组在 owner 后 2.536 s 才越过 45°，连续参考没有断流证据。

后续十轮围绕最后两段和刹停，改变整体时间尺度、末段时间尺度和进入相位。整体放慢 15%/20% 的已测点通过；放慢 10% 时仍有进入相位达到 46.29°。相同总时长的整体放慢与仅拉长尾段也不等价。结论是运动阶段与参考时间变化方式影响风险，不是已获得通用的“放慢多少就安全”。

提前进入神经的一条飞行出现 52 ms、45.764° 的短峰，在线检查漏过且后来落地。**首秒安全、在线未中止、最终落地，都不能代替整段安全证据。**

### 3.3 069 反例及变异：状态与目标接续共同作用

100 组中的 069 以实际约 1.94 m/s 接管，目标捕获为零速度，在神经持权后 0.292 s 首次超过 45°，保护前峰 49.463°。速度匹配的 070 峰 12.305°；入口状态较接近，但仍是独立运行。该对含外部流结束后的等待，不冒称持续参考场景。

围绕 069 的变异发现：

- 名义 1.6 m/s 单次通过不可靠：另一 seed 的接近实际速度点越过 45°。
- RINI1 影子历史与 RINI4 记忆/动作准备均已从原生日志核实执行，却仍达 48.427°、50.147°。历史准备不是零速目标失配的通用补救。
- 外部冻结目标与外部制动参考分别达到 56.053°、9.190°；两者的发布与经典持权存在重叠，不能称纯粹 N 独有的瞬时目标变化。
- 真正 N 活动期间超时：RTGT1 在首次激活匹配速度，但后续超时捕获回到零速度，峰 49.168°；RTGT2 也覆盖活动期间超时捕获，峰 14.313°。两例捕获初态并非完全相同，作为机制一致的描述性对照。

原 015–017 并未实现预期 active-timeout，仍保留证据缺口；不能把 activation 场景冒充超时验证。超时风险与最初接管参考空窗分阶段研究。

### 3.4 Lyapunov 引导：已经形成前瞻选点到物理反例的链条

本轮固定 069 祖先条件、seed 20261110、x500、现有策略和 RINI0 reset。经典 OFFBOARD 沿 +x 加速，在轨迹第 3 秒触发，参考结束后沿用 0.26 s 等待，再正常请求 RAPTOR；RTGT0 捕获当前位置和零速度。**这不是 Mission 重复，也没有单独改变历史。**

飞行前冻结候选量与选择规则：

```text
V = (||速度误差|| / 2 m/s)^2
  + (倾角 / 45°)^2
  + 0.25 × (||角速度|| / 2 rad/s)^2
G(H) = max [V(t) − exp(−0.5(t−t0)) V(t0)]
评分 = G(100 ms)、G(120 ms)、G(160 ms) 的平均值
```

从 1.65/1.70/1.75 m/s 初始点按评分选 1.75 附近，新增 1.725/1.775；再按新最高分选 1.775 附近，新增 1.7625/1.7875。四个新点在飞行前记录选点依据、输入 hash 和启动顺序，全部实际越过 45°。没有用飞行后的峰值倒推搜索选择。

12 次中 7 次正常完成并确认落地/disarm，5 次保护截断只确认请求 LAND 和进程退出，未确认落地。001/002/004 虽在线完成，离线短峰仍判失败。

## 4. 方向扩展与同预算比较

**20 个计划案例全部完成并独立复核，另保留 1 次未起飞的连接中断，共 21 次启动。** 有效飞行的物理任务结果为 14 次倾角越界、6 次通过；旧冻结数值约束及恢复算法独立重算同为 14 失败/6 成功。新实验代码、报告和数据仍在 Thor 本地，尚未随本 README 发布。

### 搜索与基线做了什么

固定现有策略、x500、069 祖先条件和原保护，继续采用经典 OFFBOARD 运动、参考结束后等待 0.26 s、正常请求 RAPTOR 的接管方式，无新增活动期间断流。基准为 RINI0 reset 和 RTGT0 零速捕获；这不是 Mission 单例重复。复用上一轮冻结 V 评分，没有用新结果事后改权重。

- 共享 6 个初始点：名义 1.4/1.8 m/s × NED 水平运动方向 0/45/90°。
- V 与速度误差两臂各新增 4 次飞行，只读共享初始点及本臂历史，不串用另一臂结果。
- 第一次两臂都选 1.8 m/s、45°，各自实际飞 30°/60°，重叠点分别记录成本。

## 6. 最新完成：100 次 V + fuzz 框架比较

### 下一版方法形态（建议，尚未实施）

定位为**交接语义覆盖与动态收敛反馈共同驱动的反例搜索**。三类条件共同进入框架，V 是反馈之一，目标是发现有区分度的危险组合并形成可检查的拒切条件。

1. 先按物理×历史×过程类别分配最低探索预算，再在类别内选种，避免高风险权重一直偏向已知 native 零速捕获。
2. 将历史扩展到不同前置机动、经典驻留和神经重入；核对 GRU 方向/距离、动作不连续和 teacher 覆盖，不只用 RINI 标签及范数。
3. 把激活瞬间目标/控制状态跳变与接管后持续增长分开，记录请求、ACK、active、参考读取和四电机应用；避免持权后短窗遗漏最初激活变化。
4. 比较有方向的姿态—角速度耦合，区分向安全姿态回转与继续倾倒；保留速度/角速度简单基线，预先冻结窗口和公式。
5. 探索多目标种子队列、类别内不同反馈轮换或按新增危险类别收益调节预算，不只取最大排名。用同框架去掉/加入 V 的消融检验增益，比较新危险类别及首次发现成本，而不仅计邻近重复反例。
6. 对反例做局部缩减，去掉不必要的变化，再在未参与搜索的邻点验证。最终拒切规则需使用切前状态、历史和计划接续，或经验证的短时预测；接管后 160 ms 的离线 V 不能直接作为切前规则。

这些可作为未来 Autoware 扩展的抽象框架，但具体状态、历史、交接语义和安全定义仍需重新构建，当前没有跨系统验证。
