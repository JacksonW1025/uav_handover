# 真实部署素材：神经穿缝与经典恢复控制

更新：2026-11-12。引用键：`wu_sensorimotor_2026`。这是部署论文，不是事故调查，也不是本仓库实验结果。

## 核实到的流程

Wu 等的 *Precise Aggressive Aerial Maneuvers with Sensorimotor Policies* 在真实四旋翼上采用以下接续：

**PX4 光流悬停 → 触发神经策略穿缝 → PD 姿态恢复 → PX4 光流减速与悬停。**

神经网络的穿越检测头输出达到设定数量的正值后进入恢复阶段，文中数量设为 4。这里不擅自补充“连续四次”。PD 根据飞控姿态反馈将横滚、俯仰恢复到接近零；补充材料另以 PX4 Position Mode 描述恢复与悬停。

**接口必须区分：** 策略输出总推力和机体角速度指令，由 PX4 执行，不能写成神经网络直接输出四电机命令。这与本仓库研究的 RAPTOR 电机输出交接不完全相同。

来源：[arXiv v2 全文，Real-World Deployment](https://arxiv.org/html/2604.05828v2#S4.SS4)；同时复核 Results 中硬件说明及补充材料 Optical flow-based control in recovery mode。以上为原文的简要转述，不镜像全文。

## 对我们的研究有什么用

以下是**本项目的研究推论**，不是该文作者给出的安全结论。

- 这提供了经典与神经控制在实际任务中前后接续的直接部署动机，不必只靠传统模式事故类比。
- 我们可以追问三类条件：交接时的速度、姿态及高度余量（物理）；策略启动前接受过哪些观测、如何初始化记忆（历史）；触发、指令接口、检测与恢复控制何时接续（过程）。三类问题需要分别实验，不能从这篇部署论文直接得出答案。
- 方法上，它启发我们把测试对象从单一控制器扩展到整条接续链。V 可以反馈物理响应，历史和过程仍需作为独立变异维度与记录变量。

## 写作边界

该文不是“经典→神经导致事故”的证据，也没有替本仓库证明 V 引导搜索更有效。不要把穿缝所需的大倾角直接称为危险或套用我们某个实验的 45° 限制。本文笔记不声称作者测量了 PX4 模式注册、ACK、电机所有权切换或安全拒切边界。

推荐写法：**真实部署已出现经典悬停、学习控制任务执行及经典恢复的接续流程，因此交接本身值得作为测试对象；本文进一步研究哪些物理状态、历史与接续条件会使交接不安全。** 前半句引用部署文献，后半句明确是我们的问题定位。
