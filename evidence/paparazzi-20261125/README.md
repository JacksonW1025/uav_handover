# Paparazzi UAV 四类交接试验

Paparazzi v7.0.0_stable 在 Thor 的 ARM64 容器内，使用 Bebop2 自带 NPS/JSBSim simple_x_quad 模型、同一套机载飞控。Paparazzi 正常完成 NAV 起飞，进入 GUIDED 后在宿主 C/N 外环之间交接，机载飞控保持 GUIDED，最后通过原 NAV 着陆程序落地。无真机连接。学习型外环与 ArduPilot 对照采用同构训练；固定种子 20261123。

- T1：比较 C_fast 与 N_fast，正常交接，接手方历史已经准备，读取正确目标并及时发送。关注相近入口下切换后第一段制动几何和实际减速；C_slow、N_slow 给出较慢入口。
- T2：对 N_slow 只改入口清零，观察输出跳变和姿态/逆向速度变化。
- T3：切换后故意短时把旧巡航参考给新外环。
- T4：新外环已读到新目标并计算出输出，宿主继续发送旧经典指令；观察 GUIDED 速度目标和机身变化。它验证上层交付，非电机级控制权。

真值来自 NPS 物理模型，速度输入来自 NPS 中同步采样的固件 `guidance_h.sp.speed.x`。记录器只读，不改变固件接受和执行命令的规则。以宿主首条切换拍的发送时钟插值到 NPS 模拟时间，约 100 Hz 采样，转折时间是首次观测值，没有把它当作精确 UDP/电机延迟。全部落地、结束样本电机关闭且不在飞行。原始日志和实验环境保持 Git 忽略。

## 与 PX4 结果如何对应

T1–T4 是机制映射，不是把这七次重复算成 PX4 样本。在本平台，C/N 是宿主外环，机载飞控仍执行原 GUIDED 路径；T1 观察到的是制动与距离余量差异，没有预设安全边界越界的证据。T2 是本实验外环记忆清空，不是机载 GRU 证据。T3 与 T4 用有意构造的仿真对照分离，不能解读为平台默认会自发选旧参考或延迟交付。T4 的观测边界是宿主输出选择和机载速度输入，不是电机实际样本交接。

## 来源与复核

- [指标原始导出](metrics.json)保存七组全部原精度数据、策略种子及构建指纹；[原始文件 SHA-256 清单](archived-runs.json)保留各案相对归档路径和证据身份。归档来自 Thor 既有 `uav_lab/.local/paparazzi-nps/handover-pilot`，本次整理未新增仿真。
- Paparazzi 固件链：[GUIDED 速度输入及水平制导 `guidance_h.sp.speed`](https://github.com/paparazzi/paparazzi/blob/859ce70cab56df31f19cd69af9f150fe45562d8e/sw/airborne/firmwares/rotorcraft/guidance/guidance_h.c)。固件 `sp.speed` 是输入，并非后续经制导平滑的参考。
- 宿主首条实际上送出的速度与 NPS 日志中 `guidance_h.sp.speed.x` 首次相符的样本做数值核对。制动目标门限为 `fw_vx < −0.015 m/s`。采样与对时误差使 0–7 ms 这类报告数字不应解释成精确传输时延。
- 原始 CSV、DataFlash/仿真日志、运行器及补丁不随本目录发布。
